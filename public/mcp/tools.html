ThriveStack MCP

Tools Reference

Every tool the ThriveStack MCP Server exposes, with parameters and what each one does.

The ThriveStack MCP Server exposes 77 tools across product analytics, revenue, activation, AI visibility, and account/GTM data — plus one MCP resource, analytics://schema, describing the full ClickHouse schema for hand-written queries.

Almost every tool is read-only. Only two touch state: create_account_segment (creates a segment) and start_thrivestack_setup (kicks off a telemetry install flow) — there is no delete/update surface.

None of these tools take a project_id or similar tenant parameter. Your product and environment are resolved automatically from how you authenticated (OAuth session or Personal Access Token) — see Setup.

Your AI assistant calls these automatically based on your questions. For most analytics questions, it should reach for ask first — that single tool auto-routes to the right internal data source instead of you (or the assistant) having to pick from the list below.

Response format

There is no single universal response envelope — each tool returns the JSON shape natural to its own data source (a gRPC struct, a GraphQL result, a ClickHouse row set). Tools that return tabular data generally return an array of row objects; tools with a fixed multi-field result (like get_mau_mtu_count) return a flat object. Descriptions below call out anything non-obvious about a given tool’s shape.

Tools whose description says “returns a clear empty/no-run result” or similar are explicitly designed to return an empty-but-valid result rather than an error when there’s no data yet (e.g. a domain that hasn’t been probed) — treat that as “nothing here yet”, not a failure.

Primary entry point

The ask tool is the primary interface for analytics and growth questions. Rather than mapping directly to a single backend call, it hands the question to an internal orchestrator that runs a Claude tool-use loop (up to 10 iterations) with a fixed set of ClickHouse-backed internal tools — schema discovery, signup/MRR/churn trends, activation status, feature usage, funnels, UTM/channel performance, abuse signals, and a constrained custom-SQL escape hatch. Claude decides which internal tool(s) to call, chains them when a question needs multiple data points (e.g. combining signups, MRR, and activation for a growth summary), and synthesizes the results into a business insight grounded strictly in the returned data (never estimated or recalled from training data), including markdown tables and chart artifacts for trend/comparison data where appropriate.

ask

PRIMARY TOOL — use this for ALL analytics and growth questions. Queries live ClickHouse data, picks the right internal tool automatically, and returns a business insight. Use for any question about: signups, MRR, ARR, churn, activation, retention, feature usage, accounts, users, revenue, expansion, contraction, cohorts, funnels, or trends. Do NOT answer analytics questions from memory — always call this tool. Examples: ‘Why is activation dropping?’, ‘What is my MRR trend?’, ‘Which accounts churned this month?’, ‘How many signups last month?’

ParameterTypeRequiredDescription
questionstringYesYour analytics or growth question in plain English.

Accounts

list_accounts

List CRM accounts with optional filtering and pagination. Returns account names, IDs, domains, scores, and subscription details.

ParameterTypeRequiredDescription
pagenumberNoPage number, 1-indexed (default 1)
sizenumberNoPage size (default 20, max 100)
sort_bystringNoColumn to sort by, e.g. last_active_time
sort_orderstringNoSort order: asc or desc (default desc)

get_company_name_from_contacts

Derive company name and email for CRM contacts based on filter predicates.

ParameterTypeRequiredDescription
filtersarrayYesFilters to apply to contacts. Each filter is { key, operator, value }. key: one of email, first_name, last_name, title, job_title, linkedin, phone_no, company, domain, company_type, industry, country, city, description. operator: one of eq, ne, gt, lt, gte, lte (or the long-form aliases equals, not_equals, greater_than, less_than, greater_than_or_equal, less_than_or_equal).

Acquisition & Conversion

get_account_pre_signup_journey

Interactive 3-step pre-signup journey explorer. Step 1 (step=dates): returns all acquisition dates with signup counts. Step 2 (step=users): pass selected_date + user_ids_json to get a per-user summary for that date. Step 3 (step=timeline): pass selected_user_id to get that user’s full session timeline. Always start with step=dates.

ParameterTypeRequiredDescription
stepstringYesOne of dates, users, timeline
selected_datestringNoYYYY-MM-DD. Required when step=users
user_ids_jsonstringNoJSON array of user IDs from step=dates. Required when step=users
selected_user_idstringNoUser ID. Required when step=timeline

get_conversion_analytics

Returns aggregate conversion metrics and a daily breakdown (touchpoints/time-to-signup).

No input parameters required.

AI Visibility & Content Recommendations

get_citation_probe_data

Citation-gap evidence for a domain’s most recent completed AI-visibility probe run: every tracked buyer question, our citation count vs. total, and which competitor brands appeared instead. Returns raw evidence only. Returns a clear empty/no-run result if the domain has no completed probe run yet — not an error.

ParameterTypeRequiredDescription
domainstringYesDomain to fetch citation probe evidence for

get_domain_prompts

The tracked buyer questions (prompts) generated for a domain, grouped by topic. The domain must be enriched first; if it isn’t, the resulting error message is returned cleanly rather than crashing.

ParameterTypeRequiredDescription
domainstringYesDomain to fetch generated prompts for

get_domain_report

Full visibility report for a domain’s most recent completed AI-visibility probe run: overall visibility and average position, competitor/mentioned brands, broken down by topic and by individual tracked question, with per-AI-model detail underneath each. Scoped automatically to the latest completed probe run for the domain. Returns a clear empty/no-run result if the domain has no completed probe run yet — not an error. Does not include response text or citation URLs — use get_citation_probe_data for that evidence.

ParameterTypeRequiredDescription
domainstringYesDomain to fetch the visibility report for

get_owned_content_recommendations

Content recommendations for the brand’s own site — content to publish on your blog/site to close AI-citation gaps found during probing. Each item includes a severity tier, gap score, your citations vs. total citations, and which competitors are winning as evidence. Recommendations only exist after generation has been run for the domain — an empty list can mean generation hasn’t run yet, not that there’s nothing to recommend.

ParameterTypeRequiredDescription
domainstringYesDomain to fetch owned content recommendations for
statusstringNoOne of suggested, todo, approved, dismissed (default: all active statuses, dismissed excluded)
prioritystringNoOne of HIGH, MED, LOW
channelstringNoFilter by channel, e.g. Blog
limitnumberNoMax results per page (default 100)
offsetnumberNoResults to skip (default 0)

get_earned_content_recommendations

Content recommendations for earned/third-party media — ideas for getting cited on sites like Reddit, G2, or other reference/editorial domains. Each item’s evidence type is either citation_backed (tied to a real probe gap) or category_inferred (inferred from category, no direct citation evidence) — check which one before treating a recommendation as citation-backed fact. Recommendations only exist after generation has been run for the domain.

ParameterTypeRequiredDescription
domainstringYesDomain to fetch earned content recommendations for
statusstringNoOne of suggested, todo, approved, dismissed (default: all active statuses, dismissed excluded)
prioritystringNoOne of HIGH, MED, LOW
channelstringNoFilter by channel, e.g. Reddit, G2
limitnumberNoMax results per page (default 100)
offsetnumberNoResults to skip (default 0)

generate_content_outline

Generates a content outline (structure only, not finished copy) for one owned-media content recommendation — headings, an answer-first opening summary, FAQ questions, and suggested schema markup types. Stateless and synchronous — nothing is persisted, calling it again just re-generates. Only owned-media content types are supported: Homepage, Domain, Product, Comparison, Article, Educational, Blog, Guide, How-to, Documentation, Listicle, Wiki. Earned-media content types (Social post, News, PR, User review, Research) get an outreach action instead — calling this with one returns an error.

ParameterTypeRequiredDescription
content_typestringYesOwned-media content type — one of: Homepage, Domain, Product, Comparison, Article, Educational, Blog, Guide, How-to, Documentation, Listicle, Wiki
titlestringYesThe content recommendation’s title to outline (e.g. from get_owned_content_recommendations)

ClickHouse Analytics

These tools query ClickHouse directly for your product’s raw event, revenue, and activation data. Run discover_product_schema first if you need real event/feature names — several of these accept them as inputs.

get_signup_trend

Weekly/monthly signup counts with marketing channel attribution (via device ID join to page events). Returns signups by channel, UTM source, campaign, and month-over-month change.

ParameterTypeRequiredDescription
monthsnumberNoNumber of months back from today (default 3)

get_visitor_conversion

Top-of-funnel conversion: marketing visitors → signed up → engaged in product. Step 1: unique devices from marketing page events. Step 2: devices that signed up. Step 3: signed-up users with at least one product page event. Use for landing page performance and signup quality.

ParameterTypeRequiredDescription
monthsnumberNoNumber of months back from today (default 3)

get_activation_funnel

Activation funnel showing user counts and conversion at each stage. Provide the funnel_events list from discover_product_schema output. Returns count and conversion percentage at each stage, plus median time between stages.

ParameterTypeRequiredDescription
start_datestringYesStart date YYYY-MM-DD
end_datestringYesEnd date YYYY-MM-DD
funnel_eventsstringNoComma-separated ordered event names for the funnel (from discover_product_schema). Defaults to signed_up,account_created if not provided.

get_revenue_summary

Monthly revenue from transactions. Returns revenue, transaction count, and paying customer count per month with month-over-month trend.

ParameterTypeRequiredDescription
monthsnumberNoNumber of months back (default 3)

get_mrr_trend

Monthly Recurring Revenue trend from a pre-computed view (fastest MRR query). Returns MRR plus month-over-month change per month.

ParameterTypeRequiredDescription
monthsnumberNoNumber of months back (default 6)

get_mrr_waterfall

MRR waterfall breakdown: New / Expansion / Contraction / Churn MRR for a given month, with customer names.

ParameterTypeRequiredDescription
monthstringYesMonth in YYYY-MM format

get_churn_accounts

Accounts that churned in a given month. Classifies each as hard_churn / scheduled / already_lapsed and cross-checks payments after the cancel date.

ParameterTypeRequiredDescription
monthstringYesMonth in YYYY-MM format

get_feature_usage

Top features by unique users and event volume for a date range. Returns feature name, unique users, total events, and events per user. Use discover_product_schema first to know which feature names exist.

ParameterTypeRequiredDescription
start_datestringYesStart date YYYY-MM-DD
end_datestringYesEnd date YYYY-MM-DD

get_account_journey

Full event trail for one account: all users, all milestones, all feature usage in chronological order.

ParameterTypeRequiredDescription

get_activation_status

Account counts by activation status (not_started / started / activated). Returns counts and average time to activate.

No input parameters required.

Growth Insights & Custom Queries

run_analytics_query

Execute a custom read-only SQL query against ClickHouse. Read the analytics://schema resource first to know the tables and rules. The query MUST include both product_id and environment_id in the WHERE clause — they are validated before execution. DDL and DML are rejected.

ParameterTypeRequiredDescription
sqlstringYesSELECT query to execute. Must filter on product_id and environment_id.

explain_growth

Aggregate growth data across signups, revenue, features, and the activation funnel for a period. Returns structured data with interpretation rules for growth-advisor-style reasoning on top. Run discover_product_schema first.

ParameterTypeRequiredDescription
monthsnumberNoNumber of months to analyze (default 3)

explain_churn

Churn analysis for a given month. Returns churned accounts with classification (hard_churn / scheduled / already_lapsed), LTV, last payment date, and event trail for each account.

ParameterTypeRequiredDescription
monthstringYesMonth in YYYY-MM format

explain_activation

Activation analysis: funnel drop-off points, time to each milestone, accounts stuck at each stage. Returns data for identifying primary activation blockers.

ParameterTypeRequiredDescription
start_datestringYesStart date YYYY-MM-DD
end_datestringYesEnd date YYYY-MM-DD

Schema Discovery

discover_product_schema

Run this FIRST before any analysis. Discovers all event names, feature names (inside feature_used events), funnel sequence order, and AHA-moment candidates for this product/environment. Returns the event taxonomy needed to write correct queries — never hardcode event names without running this first.

No input parameters required.

Monthly Metrics Scorecard

get_monthly_metrics_table

Returns a month-by-month scorecard covering the full PLG funnel: new visitors, repeat visitors, signups, time-to-signup, touchpoints-before-signup, new paying accounts, and new MRR. Each cell is color-coded (green/yellow/red) relative to all months in that column, so it’s easy to spot strong or weak months at a glance. Covers the last 12 months. Use this when the user asks to diagnose conversion/acquisition/revenue health, understand why MRR or signups dropped, see a conversion scorecard, or identify the worst-performing month.

No input parameters required.
